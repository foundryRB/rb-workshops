## Context

The workshops engine is part of the RB Software Engineering install. Its application,
documentation and rendered instruments need a consistent identity. The canonical
workshop renderer has separate use modes: a dark presentation stage and a light
facilitator script.

## Decision

The application and documentation use the RB Software Engineering lockup, the
system font stacks and the RB Software Engineering colours. The application
offers Light, Dark and System appearance; its forms and editors retain solid,
readable surfaces. Monospaced values use Cascadia Code, Consolas and monospace.
Outcome colours retain their labels and semantic meanings.

Workshops are rendered from the exact canonical template pinned by renderer.lock.
That template contains its palette, faces, mark and decoration, and fixes the room
to Dark roles and the facilitator script to Light roles. The application consumes
the artifact without restyling its document. A template change requires a matching
renderer pin and engine release.

## Consequences

The typography claim tests the system sans stack at the display and body roles and the maintained
system mono stack at identifiers. Accessibility checks cover both application
appearances. Exported workshops retain their identity and work offline.
