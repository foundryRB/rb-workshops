## Context

The workshop stands as run: a closed run's capture and artifact are immutable (RUN-004). Refused through all three doors, or the API is the way to edit history.

## Decision

The close is one act in the core: land the final capture, render the artifact, store its bytes and sha256 with the renderer pin, and mark the run closed. The core refuses any further land or close on a closed run before a door is involved, so the UI, the API and the MCP door cannot differ; the database refuses any update to a closed run and any delete of a run.

## Rationale

- Immutability is a core rule, not a per-door check, so it cannot be bypassed by a new door.
- Freezing the artifact bytes at the close makes the run's export the same bytes forever, whatever the renderer's pin later does.

## Alternatives considered and rejected

- **Re-rendering a closed run's artifact on demand**: a re-render after a pin bump would change a closed run's export.
