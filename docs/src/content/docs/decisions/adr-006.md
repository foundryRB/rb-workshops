**Date**: 2026-09-29
**Status**: Decided

## Context

The engine is private by default behind the identity realm, and the MCP door is a machine endpoint an agent cannot reach through a browser login. The platform's contract puts a machine-door key the app hands to a signed-in person in the app's own chart, minted in-cluster like the grants' credentials, so nobody needs the value before it exists and no hand applies it.

## Decision

The sidecar runs `--provider=oidc`, skips `^/mcp(/|$)` and `/api/health` with `--skip-auth-strip-headers=false`, and treats `/api/` as API routes so a machine gets 401 rather than a redirect. The engine serves its human surfaces only under `WORKSHOPS_AUTH_SCOPE=mcp`, the shape the chart runs, and 503 otherwise. The key lives in Secret `rb-workshops-mcp-auth`, minted by a sync-wave Job ahead of the Deployment, which reads it by required reference; the doors page returns it to a signed-in person as a ready connect command. The door answers 503 until the key exists and 401 on a wrong one.

## Rationale

- One credential per audience: the realm for people, a key for agents.
- A chart-minted key removes the out-of-band apply from the deploy path and keeps the machine door usable from the first sync.

## Alternatives considered and rejected

- **A key applied out of band from a committed template**: the platform's model for values the cluster cannot generate; this value it can, and the deploy path holds no cluster access for the apply.
- **Routing the machine door through the interactive gate**: an agent cannot complete a browser login.
