## Context

Every revision kept and retrievable is the shelf principle the library established, and the requirement (STORE-001) names it. The lifecycle names ephemeral and draft, and the approved shelf counts a third, published.

## Decision

The store port exposes no update or delete of a revision, and the PostgreSQL schema refuses both with a trigger, so a direct connection as the owner role cannot rewrite history either. The shelf state is a forward-only column: a session is created ephemeral, becomes draft on its first saved revision and published on its first successful publish; a trigger refuses any backwards transition. A revision's dataset is stored as text-preserving JSON so the author's key order survives and the export serializes it byte for byte.

## Rationale

- The falsifiable form of append-only is that a write path which mutates a revision does not exist, at every layer.
- Two independent enforcements mean the guarantee does not rest on adapter discipline alone.

## Alternatives considered and rejected

- **Soft deletes or in-place edits with history tables**: history as a side table is history that can be dropped; the revision is the record.
- **A JSONB column**: it reorders keys and would break byte-identity between the stored dataset and a fresh render.
