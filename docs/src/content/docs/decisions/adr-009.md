**Date**: 2026-09-29
**Status**: Decided

## Context

The publisher holds a repository-scoped write credential; neither a fine-grained token nor a deploy key can be narrowed to one ref. A defect in the publish path would otherwise have a route into the branch that cuts releases.

## Decision

The publisher takes the ref it is asked to write and compares it with the configured home ref before it builds a client; a mismatch raises and nothing is sent. Constructing a publisher with a home ref that is the default branch, a deploy branch or a delivery ref is refused outright. The guard is a unit claim that passes with no credential, no namespace and no cluster.

## Rationale

- A guard in the code holds even if the credential is later widened.
- Deciding before the connection opens means a refused publish leaves no trace on the remote.

## Alternatives considered and rejected

- **Relying on the token's scope**: no scope below the repository exists.
- **Seeding the delivery credential as the publisher's**: it can write the default branch; the exposure the guard exists to prevent.
