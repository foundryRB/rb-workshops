**Date**: 2026-09-29
**Status**: Decided

## Context

The customer asked for the bootstrap-workshop template as the one canonical renderer, consumed rather than forked, with divergence a playbook change first. The template ships as a corpus file with no package and no version, so the identity that can be pinned is its content hash. The corpus is private: the playbook-studio door takes a credential, and the shared CI's image build holds none, so a build-time fetch cannot produce a deployable image. Vendoring the bytes into this tree, the fleet's usual answer, is forbidden for this engine by name.

## Decision

The repository carries `renderer.lock`, the sha256 of the template, and a source-level test that no copy of the template is inside the tree. At start the engine resolves the bytes from the first source configured, a file the environment names, the cache a previous fetch left, or the playbook-studio door over its MCP protocol with the credential the environment carries, and refuses to render when the bytes hash to anything else. The credential is an external fact the install seeds out of band, as it seeds the publisher's; until it exists the engine serves everything but a render, and says so on its health route and its doors page. The injection procedure is the engine's and deterministic: the dataset as two-space JSON into the session-data block, the title into the document, so an export equals a fresh render byte for byte. Each export records the pin beside it, never inside it.

## Rationale

- A content hash is a stronger anchor for byte-identity than a semver, and the only one the corpus offers.
- Resolving at runtime keeps the tree free of the template and the image buildable with no credential, at the cost of one more seeded secret.
- The pin check at every source means a moved template fails loud rather than rendering something else.

## Alternatives considered and rejected

- **A vendored, pinned copy in the tree**: hermetic, the fleet's precedent, and forbidden for this engine by the delivery's authorization.
- **A build-time fetch in the image build**: no credential reaches the shared CI's Docker build.
- **A published versioned artifact of the template**: the right long-term shape, recorded as the evolution item that would let a later build take it; it does not exist yet.
