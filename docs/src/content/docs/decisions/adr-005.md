**Status**: Decided

## Context

Publishing writes an export to a git-backed home and never mutates the store (EXP-003). The home named on the approved prototype does not exist, and minting a repository is outside the delivery's authorization.

## Decision

The home is read from configuration: repository, ref, path template and the credential's mounted file. The default is this repository's orphan branch `home`, which carries no workflow, so a publish fires no release and the GitOps application never watches it. Re-pointing the home at a dedicated repository later is a configuration change. A publish reads the store and writes git; it holds no write path back into the store, and it records the publication beside the runs.

## Rationale

- Configuration over an existing, already-private surface is the least-exposure default that still reaches the done-definition.
- An orphan branch keeps published exports out of the release train's history.

## Alternatives considered and rejected

- **A new dedicated repository**: not authorized for this delivery, and a config change away once it exists.
- **Committing exports onto the default branch**: every publish would cut a release.
